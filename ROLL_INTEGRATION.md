# Поддержка будущих бросков из виджета

Исследовано 11.10.2026: Forbidden Lands **13.0.5**, Roll Dialog Plus **0.7.1**
([исходники](https://github.com/Mishokkka/roll-dialog-plus/tree/ccff08b6359f081a51e5a22f9b90c5248467b3db)).

Roll Dialog Plus заменяет оформление штатного `FBLRollHandler` через события
рендера. Его публичный API предоставляет профили, quick-группы и расчёт
вероятностей, но не открывает окно броска. Поэтому виджет использует публичные
методы текущего листа, без импорта файлов другого модуля и собственной формулы:

| Операция | Штатный вызов | Результат |
| --- | --- | --- |
| Атака оружием в руках | `actor.sheet.rollGear(itemId)` | Навык/характеристика, бонус и damage metadata оружия берутся системой. |
| Уклонение | `actor.sheet.rollAction("dodge")` | Move-бросок; Roll Dialog Plus распознаёт профиль Dodge. |
| Парирование оружием/щитом в руках | `actor.sheet.rollAction("parry", itemId)` | Melee-бросок с Item и профилем Parry. |

`rollAction("attack", itemId)` не используется: в этой версии системы метод
обнуляет `data.gear.damage` для действий с предметом. Штатный бросок оружия
сохраняет сведения атаки. Push, повреждение снаряжения, таланты, artifact dice,
модификаторы и чат остаются в системном backend и Roll Dialog Plus.

## Что уже готово

```js
const rolls = game.modules.get("yze-combat-permission-fix")?.api?.rolls;
const state = rolls?.getState();
const weapon = state?.items.find(item => item.attack);
if (state?.available && weapon) {
  const app = await rolls.open({
    kind: "attack", actorUuid: state.actorUuid, itemId: weapon.itemId,
    expectedRevision: state.equipmentRevision,
  });
  // Открыто окно выбора параметров; бросок ещё не выполнен.
}
```

`actorUuid` обязателен, а ревизию следует передавать из показанного снимка.
Проверяется владение текущим персонажем, точная версия системы, возможность
действовать, незавершённая манипуляция, наличие Item, его исправность и отметка
хвата. Щит разрешён для парирования; факел не становится оружием. Двуручный
предмет появляется в списке один раз. Предмет нельзя автоматически извлечь из
слота перед атакой: сначала игрок выполняет отдельную манипуляцию с выбранной
стоимостью. Хват остаётся ручной отметкой, требования двух рук не угадываются.

Без Roll Dialog Plus открывается штатное окно. Без Quick Access доступно
уклонение; броски предметом требуют его equipment API. Чтение состояния не
пишет флаги; открытие окна не списывает действия и не выполняет submit.
Кнопки атаки/уклонения/парирования пока не добавлены в интерфейс.

## Следующий этап интерфейса и оплаты

В меню удерживаемого оружия можно добавить «Атака» и «Парирование»; «Уклонение»
подходит для общей компактной панели реакций. Вначале открывается системный
диалог, где игрок выбирает параметры Roll Dialog Plus. Отмена окна не расходует
действие. Стоимость броска должна выбираться явно по договорённости стола;
имеющийся журнал манипуляций нельзя выдавать за транзакцию броска.

События Roll Dialog Plus:

- `fblRollDialogPlusPrepare` предоставляет `app`, `actor` и контекст; интеграция
  должна связывать его с конкретным возвращённым Application/Actor.
- `fblRollDialogPlusBeforeRoll` допускает запрет отправки через `false`.
- `fblRollDialogPlusSubmissionAttempted` сообщает попытку, а не успешный бросок.
- `fblRollDialogPlusRollSubmitted` приходит после подходящего ChatMessage:
  `message`, `context`, `metadata`, `nonce`, `userId`, `actorId`.

Будущая оплата требует отдельной записи намерения: идентификатор операции,
Actor UUID, Item, бой/раунд, выбранная цена и подтверждение конкретного сообщения.
Повтор события, Push и одновременные окна одного Actor не должны повторять
списание. Нельзя связывать бросок только по имени персонажа, единственному
контролируемому токену или первой карточке чата. После отмены/сбоя следует
очищать ожидание; при частичной оплате — показывать восстановление, как для
манипуляций. Для нативного окна без Roll Dialog Plus понадобится собственное
надёжное сопоставление ChatMessage; до его реализации автоматическая оплата
бросков остаётся выключенной.

## Проверено и границы

Шесть регрессий адаптера проверяют вызовы штатных методов, владение, UUID,
ревизию, исправность и хват Item, отсутствие обоих модулей, неподдерживаемую
версию, блокировку при операции и распространение ошибки системного окна.
Профили Dodge/Parry проверены непосредственно по исходникам Roll Dialog Plus.
Код исправления перехода раунда и механизм оплаты экипировки не изменены.
Открытие настоящих окон, synthetic Actor, Dice So Nice, Push и подтверждение
сообщений требуют приёмочной проверки в живом мире с GM и игроком перед
выпуском кнопок бросков/автоматической оплаты.
